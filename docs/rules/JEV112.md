# JEV112 undefined-boundary

A Noul with no criteria turns on a word such as large, often or enough.

On by default, as `info`. A wording rule. It matches patterns in English text, so it can miss a defect or flag a question that is fine.

## Flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "noul",
      "instructions": "Is the order large?"
    }
  }
}
```

> This question turns on a word with no stated line, so Jev reads it at face value and may draw the line elsewhere. Say where yes ends and no begins in the instructions or in 'true' and 'false' criteria.

## Not flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "noul",
      "instructions": "Is the order large?",
      "criteria": {
        "true": "The order is at least one pallet or needs a lorry.",
        "false": "The order is loose items a person could carry."
      }
    }
  }
}
```

## Fixing it

There is no automatic fix. The change is yours to make.

## Silencing it

In code, on the line above:

```ts
// jevlint-le-disable-next-line JEV112
```

In JSON, which has no comments, by question id in `jevlint-le.json`:

```json
{ "ignore": ["JEV112:your-question-id"] }
```
