# JEV004 no-fallback-option

A Choice has no `other` or `none of the above`, so an input that fits no option is forced into one. The largest cost measured anywhere, and the hardest to tell from text.

On by default, as `info`. An exact rule. It reads the shape of the question and does not guess.

## Flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "choice",
      "instructions": "Which team should handle this?",
      "criteria": {
        "billing": "Charges, invoices and payment problems",
        "technical": "Faults, errors and outages"
      }
    }
  }
}
```

> This Choice has no fallback option, so an input that fits none of them is forced into one. Measured: with no fallback, every input that fit no option was answered wrong. Add 'other' or 'insufficient_evidence', or suppress this if the options cover every input.

## Not flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "choice",
      "instructions": "Which team should handle this?",
      "criteria": {
        "billing": "Charges, invoices and payment problems",
        "technical": "Faults, errors and outages",
        "other": "Fits none of the other options"
      }
    }
  }
}
```

## Fixing it

A quick fix is offered on the lightbulb: Add an 'other' option. It is never applied by `--fix` or on save, because it changes what a working request does.

## Silencing it

In code, on the line above:

```ts
// jevlint-le-disable-next-line JEV004
```

In JSON, which has no comments, by question id in `jevlint-le.json`:

```json
{ "ignore": ["JEV004:your-question-id"] }
```
