# JEV107 negated-noul

A Noul with no criteria is phrased so that yes means something is absent.

Off by default. Turn it on in `jevlint-le.json` with `{ "rules": { "JEV107": "warning" } }`. A wording rule. It matches patterns in English text, so it can miss a defect or flag a question that is fine.

## Flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "noul",
      "instructions": "Is the message free of personal data?"
    }
  }
}
```

> This yes/no question is phrased so that yes means something is absent. Jev reads that less reliably. Ask whether the thing is present and invert the answer in code.

## Not flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "noul",
      "instructions": "Does the message contain personal data?"
    }
  }
}
```

## Fixing it

There is no automatic fix. The change is yours to make.

## Silencing it

In code, on the line above:

```ts
// jevlint-le-disable-next-line JEV107
```

In JSON, which has no comments, by question id in `jevlint-le.json`:

```json
{ "ignore": ["JEV107:your-question-id"] }
```
