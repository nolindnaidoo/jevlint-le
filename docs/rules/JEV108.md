# JEV108 inverted-criteria

A Noul's 'true' criterion describes the negative case.

Off by default. Turn it on in `jevlint-le.json` with `{ "rules": { "JEV108": "warning" } }`. A wording rule. It matches patterns in English text, so it can miss a defect or flag a question that is fine.

## Flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "noul",
      "instructions": "Does the message contain personal data?",
      "criteria": {
        "true": "No personal detail appears.",
        "false": "A name, address, phone number or email appears."
      }
    }
  }
}
```

> The 'true' criterion describes the negative case and 'false' the positive, against a question asked in the positive. Align the criteria with the question.

## Not flagged

```json
{
  "model": "jev-1.13.0",
  "questions": {
    "q": {
      "type": "noul",
      "instructions": "Does the message contain personal data?",
      "criteria": {
        "true": "A name, address, phone number or email appears.",
        "false": "No personal detail appears."
      }
    }
  }
}
```

## Fixing it

There is no automatic fix. The change is yours to make.

## Silencing it

In code, on the line above:

```ts
// jevlint-le-disable-next-line JEV108
```

In JSON, which has no comments, by question id in `jevlint-le.json`:

```json
{ "ignore": ["JEV108:your-question-id"] }
```
